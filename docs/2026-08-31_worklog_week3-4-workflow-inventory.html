Workflow Cleanup & Documentation

Inventory structure established, audit pull outstanding

Prepared for Josh LeClair by John Carlo Caintic · Marketing Strategy & Automation · August 31, 2026

Item 1 of the Week 3-4 roadmap covers building a documented inventory of every workflow in the account, so that problems like a workflow silently stuck in Draft become visible instead of sitting unnoticed. This log records the structure put in place for that inventory, the four audit items still to be confirmed against the live account, and the single next step required to move forward.

1. What Was Done

Scope note: this session set up the structure for the workflow inventory. The inventory itself cannot be pulled without access to the live GHL workflow list, so this covers preparation and the capture format, not the audit findings.
  1. Created a dedicated, self-contained workspace for this account. All Window Valet files live in one isolated folder. Nothing related to this account is stored alongside or shared with any other work.
  2. Built the workflow inventory capture format. A single reference index covering, per workflow: name, status, last updated, folder, category, trigger, what it does, who it notifies, how it exits, anomaly flag, and recommended action. This is the lookup table from step 7 of the roadmap, built up front so it fills in as the audit runs rather than being assembled at the end.
  3. Pre-sorted the documentation into the seven functional categories. Lead intake, appointment lifecycle, response and escalation, nurture, partner, recovery, and internal/admin. Sorting the structure first is what makes duplication visible, which is how the two mismatched reminder emails surfaced in the first place.
  4. Wrote the capture guide. Exact navigation path in GoHighLevel and the precise fields to record, so the inventory pull is a mechanical step rather than a judgement call, and so it produces the same result if someone else runs it later.
  5. Established the documentation pipeline. Every task from here produces a written record in this format, source file plus PDF. This document is the first one.

3. Open and Blocked

  1. The inventory pull itself is outstanding. Steps 1 and 2 of the roadmap require working directly in the live workflow list. Everything downstream depends on this.
  2. Steps 5 and 6 are deliberately held. Fixing overlaps and archiving obsolete workflows should not happen until the full inventory has been reviewed and signed off. Archiving is the one step here that is difficult to reverse, and a workflow that looks dead may still be enrolling contacts.
  3. One open question: are workflows currently organised into folders, or is it a single flat list? This determines whether the seven categories become real folders in the account or stay as a documentation-only structure.

4. Next Step

Pull the complete workflow list from the account, unfiltered, capturing name, status, and last-updated date for every workflow. Categorisation, the plain-English write-ups, and the completed reference index follow directly from that list.
